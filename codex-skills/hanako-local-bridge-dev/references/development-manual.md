# Hanako Local Bridge Development Manual

Manual revision: 1

## Non-negotiable Product Direction

- Develop new Hanako Local Bridge product functionality only in Rust under `apps/` and `crates/`.
- Treat Hanako Local Bridge as one product with one Windows installer, one manager entry, one
  configuration model, one product version, one update policy and one diagnostic/repair flow.
- Treat Bridge, Manager, Maintenance, Bootstrap and Device Router as internal modules, build targets
  or runtime roles. They are not independent products.
- Multiple internal processes are allowed for background survival, self-update replacement,
  operating-system separation and fault isolation. They must remain invisible as separate products
  to the user.
- Keep search, transactions, history, sync and cognitive event support in the same repository,
  protocol family and management experience. Separate RFCs or milestones do not create separate
  products.
- Keep legacy Node, PowerShell, VBS and WinUI code only for migration, compatibility, overwrite
  takeover and rollback tests. Do not add product features to legacy implementations.

## Environment Preflight

Run `inspect-environment.ps1` before editing. Confirm:

- repository root and remote;
- current branch, commit, tag and dirty files;
- workspace and stable package versions;
- Rust, Cargo, Node, npm, Git and GitHub CLI availability;
- signing key presence without reading or printing it;
- release and Debug binaries;
- installed Bridge health and version;
- scheduled task, ports and process window state.

Windows command rules:

- use PowerShell-native file operations;
- use `rg`/`rg --files` for search;
- use `npm.cmd` and `npx.cmd`;
- invoke repository scripts through
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`;
- do not use Bash heredocs in PowerShell;
- do not print token or credential file contents.

When MSVC is not loaded, initialize Build Tools before Cargo:

```powershell
$vcvars = 'C:\BuildTools2026\VC\Auxiliary\Build\vcvars64.bat'
$lines = cmd.exe /d /s /c "`"$vcvars`" >nul && set"
foreach ($line in $lines) {

    [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
  }
}
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
```

## Daily Development Workflow

### 1. Define the observable result

Write a concrete pass condition:

```text
Example: closing the manager leaves 8787/8788 healthy and hanako-bridge has no visible window.
```

Avoid goals such as "make service stable" without a deterministic probe.

### 2. Protect current state

```powershell
git status --short --branch
git diff --stat
```

Do not reset, checkout or overwrite unrelated user changes. Use a temporary worktree for bisecting
or experiments that require a clean tree.

### 3. Diagnose or design

For bugs:

- reproduce the exact entry point;
- capture process, port, task, health, log or state evidence;
- state one root-cause sentence naming a file/function/condition;
- add a regression test that fails before the fix.

For features:

- identify the owning module;
- define compatibility and security boundaries;
- add the smallest interface that fits existing patterns;
- identify required migration and payload effects.

### 4. Implement narrowly

- use `apply_patch` for manual source edits;
- keep comments limited to non-obvious constraints;
- do not mix Legacy cleanup with Rust feature work;
- preserve unknown configuration and files;
- do not change cloud and Windows protocol independently without compatibility handling.

### 5. Validate in layers

Run the narrowest test during iteration. Run the complete release gate only after source and
documentation stabilize.

### 6. Verify the real runtime

Native, tray, scheduled task, update and installer changes require a real Windows check. Cloud
changes require the complete device path, not only local unit tests.

### 7. Close the maintenance loop

- update version and changelog when product behavior changes;
- update affected repository manuals;
- refresh the Skill snapshot;
- validate and sync the Skill if its instructions changed;
- commit only intended files and push the selected branch/tag.

## Debugging Playbooks

### Service unavailable

Check in order:

```powershell
Get-ScheduledTask -TaskName 'Hanako Local FS MCP'
Get-ScheduledTaskInfo -TaskName 'Hanako Local FS MCP'
netstat -ano | Select-String ':8787|:8788'
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -like 'hanako*' } |
  Select-Object Name, ProcessId, ParentProcessId, CommandLine, ExecutablePath
Invoke-RestMethod http://127.0.0.1:8787/health
Invoke-RestMethod http://127.0.0.1:8788/health
```

Distinguish:

- task missing;
- task ready but process absent;
- port owned by Legacy process;
- health reports wrong version;
- Bridge local health good but cloud status offline;
- Manager is broken while Bridge remains healthy.

### Visible console window

Inspect installed PE subsystem and process window handle. Release Bridge must be subsystem `2`
(`WINDOWS_GUI`) and `MainWindowHandle=0`. Hidden Task Scheduler settings alone do not suppress a
console allocated by a CUI executable.

### Process does not recover

Export task XML and confirm:

```text
LogonTrigger
TimeTrigger
Interval PT1M
MultipleInstancesPolicy IgnoreNew
RestartOnFailure
```

Force-terminate the installed Bridge only when authorized. Wait for a different PID and repeat
health/window checks. A result of `0xFFFFFFFF` after external termination may not use the normal
failure-restart path; the periodic trigger is the recovery guard.

### Online update appears to fail

The old Bridge can close the HTTP connection while handing off to the update worker. Inspect:

```text
data\update-state.json
payload-manifest.json
logs\update.log
8787/health
8788/health
desktop and Start menu shortcut targets
uninstall DisplayIcon and DisplayVersion
```

Do not trigger the update repeatedly while a worker is active.

### Node integration reports an old version

Build `target\debug` explicitly before running Node Rust tests:

```powershell
cargo build --workspace
```

Cargo test binaries under `target\debug\deps` do not guarantee the root Debug EXE was refreshed.

### PowerShell script cannot run

Use:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\path\script.ps1
```

Do not change the machine execution policy as a workaround.

### Multiple computers route to one device

Verify:

- each computer has a distinct stable device ID;
- each Bridge reports `cloud.status=active`;
- browser identity corresponds to the current computer;
- cloud device list includes all devices;
- Agent tool call carries the intended `deviceId` or `device://` path;
- Device Router cache is fresh and reports the same online device.

## Coding And Compatibility Rules

- Keep Windows path handling structured; avoid ad hoc splitting.
- Resolve paths before authorization checks and prevent parent escape.
- Keep request and image size bounds.
- Preserve text encoding and BOM on rewrite.
- Use atomic writes for config, state and file replacement.
- Use SHA256 preconditions when concurrent modification matters.
- Keep audit records for approvals, executions and sensitive file actions.
- Use detached workers only when the caller must survive replacement.
- On Windows, use `CREATE_NO_WINDOW` for helper processes that should remain invisible.
- Keep Manager and Bridge processes independent.
- Treat update payload ownership as an explicit manifest, not directory-wide deletion.

## Versioning And Git

For product behavior changes:

1. bump the workspace version;
2. allow Cargo to update all workspace package versions in `Cargo.lock`;
3. update tests that assert the version;
4. add `CHANGELOG.md`;
5. update current-version sections in repository manuals;
6. build artifacts using the same committed version;
7. commit before publishing;
8. create an annotated tag and GitHub prerelease for Alpha builds.

Do not publish from a dirty worktree. Do not overwrite an existing tag or release artifact.

Pure Codex Skill maintenance is repository tooling, not a product binary release. Track it in Git,
refresh `repo-snapshot.md`, validate it and sync the installed copy without fabricating a new
runtime artifact.

## Known Hazards

- `npm.ps1` may be blocked; use `npm.cmd`.
- Directly invoking `.ps1` may be blocked; use `powershell.exe -ExecutionPolicy Bypass -File`.
- Console encoding can corrupt Chinese CLI arguments passed to generators; validate UTF-8 files.
- `Get-NetTCPConnection` can be permission-sensitive; use `netstat -ano` as a lower-layer check.
- Task Scheduler `Hidden` does not change the PE subsystem.
- A manager update request timeout does not prove update failure.
- Running Node integration against a stale root Debug EXE produces misleading version failures.
- Do not use manual empty renderer assets or hand-built placeholders to bypass build requirements.
- Do not expose a remote command-execution HTTP endpoint as a shortcut for SSH or MCP control.
- Do not put credentials into manuals even when the repository is private.

## Definition Of Done

- The user-visible behavior is verified through the real entry point.
- Root cause and regression guard exist for a bug.
- Relevant unit/integration/native/installer/update tests pass.
- Persistent data and security boundaries are preserved.
- Version and artifacts match when a product release is made.
- GitHub and VPS state match the committed release.
- Stable feed remains unchanged during Alpha publication.
- Documentation and Skill snapshot are current.
- Worktree contains no accidental files or unrelated reversions.
